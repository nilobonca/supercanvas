Arquitetura de Armazenamento Universal
⚡
3 Modos de Acesso ao Vault com a Mesma Interface:
  1. Navegador Web + Pasta Local (File System Access API): O usuário clica em "Abrir Pasta" no Chrome/Edge e o app lê/grava diretamente nos arquivos .md do HD.
  2. Navegador Web + IndexedDB (Fallback Seguro): Armazenamento interno no banco local do navegador.
  3. Desktop Windows (.exe com Electron): Acesso total ao disco rígido nativo via Node.js fs sem diálogos de permissão do navegador.

01
Fundação — Storage Adapter, Pasta Local no Navegador & TipTap
Acesso a pastas físicas do computador diretamente pelo Chrome/Edge
● NEW

Storage Adapter Universal

src/modules/vault/storage/VaultStorageAdapter.ts

Interface única para salvar e ler notas independentemente de onde elas residem (HD físico via navegador, IndexedDB ou Electron).

export interface VaultStorageProvider {
  type: 'fsa' | 'idb' | 'electron';
  readDocument(path: string): Promise<string>;
  writeDocument(path: string, content: string): Promise<void>;
  listDirectory(path?: string): Promise<VaultNode[]>;
  createFolder(path: string): Promise<void>;
  deleteItem(path: string): Promise<void>;
}
● NEW

FSAStorageProvider (File System Access API)

src/modules/vault/storage/FSAStorageProvider.ts

Permite ao usuário abrir uma pasta do Windows diretamente pelo navegador com window.showDirectoryPicker().

  • Lê todos os arquivos .md existentes na pasta do Windows.
  • Grava alterações de volta no arquivo físico instantaneamente.
  • Armazena o FileSystemDirectoryHandle no IndexedDB para reconexão automática sem pedir a pasta novamente.
● NEW

VaultEditor (TipTap WYSIWYG)

src/modules/vault/components/VaultEditor.tsx

Editor com suporte a Markdown, tabelas, tarefas e toolbar flutuante, conectado diretamente ao Storage Provider ativo.

● NEW

VaultSidebar (Árvore de Pastas e Arquivos)

src/modules/vault/components/VaultSidebar.tsx

Renderiza a hierarquia de pastas físicas do HD com suporte a criar novas subpastas, renomear e arrastar arquivos.

Plano de Verificação Completo
Critérios de teste para cada fase

Fase 1 — Fundação & Pasta Local no Navegador

  • No Chrome/Edge, clicar em "Abrir Pasta Local" e escolher uma pasta do Windows com arquivos .md.
  • Verificar que as notas e subpastas aparecem na sidebar imediatamente.
  • Editar uma nota no TipTap e verificar que o arquivo físico no Windows foi atualizado no Bloco de Notas.
  • Recarregar a página (F5) e verificar reconexão automática com a pasta do HD.

Fase 2 — Core Obsidian

  • Digitar [[ e verificar autocomplete de notas da pasta física.
  • Verificar atualização instantânea do painel de Backlinks ao referenciar notas.
  • Navegar rapidamente com Ctrl+P (Command Palette).

Fase 3 — Integração

  • Arrastar nota da pasta para o Canvas de Áudio e verificar criação do card.
  • Vincular Pin do mapa a arquivo .md e abrir com Ctrl+Click.

Fase 4 — Avançado

  • Renderizar Grafo de Conexões D3 mapeando todos os links entre notas da pasta.
  • Criar notas usando templates de RPG (NPC, Quests, Locais).

Fase 5 — Desktop Windows (.exe)

  • Gerar o instalador .exe com npm run electron:build.
  • Instalar no Windows e testar execução offline com atalhos globais de teclado da Soundboard.
